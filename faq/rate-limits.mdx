title: "速率限制"
description: "了解源力 API 的速率限制与应对方式。"
---

速率限制用于控制单位时间内可发送的请求数量，以保障服务稳定性和资源的公平分配。

## 触发时的表现

超出速率限制时，请求会返回 `429 Too Many Requests`。这属于临时性失败，通过合理的重试策略即可恢复。

## 视频任务并发

视频生成是异步任务制，除接口限流外还有单独的并发约束：

* **在途任务 ≤ 2**：单个 API Key 同时在途的视频任务不超过 2 个，提交前先查询已有任务的状态，或等任务完成后再提交。
* **轮询间隔 ≥ 5 秒**：查询任务状态的接口本身轻量，但请勿高频轰炸，间隔低于 5 秒容易触发限流。
* **下载不消耗配额**：任务完成后的 `video_url` 直连对象存储，下载不经过网关、不消耗 API 配额。

生成耗时参考：6 秒 × 50 步 ≈ 2 分钟，完整说明见[视频生成指南](/multimodal/video-generation)。

## 应对方式

* **指数退避重试**：收到 `429` 后不要立即高频重试，按小预算的指数退避间隔重试，超过预算后返回可控的失败。
* **请求排队与削峰**：在应用侧维护请求队列，平滑请求峰值，避免瞬时并发打满配额。
* **合并与缓存**：对重复前缀的对话利用缓存命中价格与缓存结果，减少实际请求量。
* **提升配额**：如果你的业务需要更高的并发或速率，请通过控制台或联系平台支持评估配额调整。

<Note>
  速率限制具体配额以控制台和平台公告为准。如果请求被限流，响应中的信息与 `trace ID` 可用于反馈问题，见[错误码](/faq/error-codes)页的排查上下文说明。
</Note>
