Origin Power (origin-power.com) provides one OpenAI-compatible API gateway for the models available to your account — covering model calls, coding-tool integration, an online playground, and usage management — with unified keys, catalog, and console so teams can bring LLM capabilities into their products quickly.

## Platform capabilities

<CardGroup cols={3}>
  <Card title="Model calls" icon="brackets-curly">
    Call the models available to your account through one OpenAI-compatible Chat Completions API, from business systems or dev tools.
  </Card>
  <Card title="Coding-tool integration" icon="terminal">
    Connect Claude Code, Cursor, Codex, and other AI coding tools by swapping the base URL.
  </Card>
  <Card title="Online playground" icon="play">
    Pick a model, adjust parameters, and see the output instantly — no code required.
  </Card>
  <Card title="Model catalog" icon="boxes">
    Browse each model's positioning, context length, and price to choose by task.
  </Card>
  <Card title="Keys and organizations" icon="key">
    Create `agw_`-prefixed API keys in the console and manage organization members and permissions.
  </Card>
  <Card title="Usage and billing" icon="gauge">
    Track request volume and token consumption, and review the organization wallet and invoices.
  </Card>
</CardGroup>

## Explore models

The platform catalog aggregates general-purpose and coding models from major vendors. Head to the [Model overview](/en/models) for each model's positioning, context length, and price — or try models right away in the [Playground](http://maas.dev.origin-power.com/en/playground).

## Core concepts

<Tabs>
  <Tab title="Model IDs">
    <Card title="Model ID — model identifier" icon="brackets-curly">
      The `model` field in a request must use the exact ID from the catalog (for example `glm-5.2`) — not a display name or alias. ID naming differs across vendors, and the available set changes as the catalog updates.

      Call `GET /v1/models` at any time to list every model ID available to your key; verify once before shipping a configuration.
    </Card>
  </Tab>
  <Tab title="Tokens">
    <Card title="Token — text processing unit" icon="coins">
      A token is the basic unit models use to process text — intuitively a "word" or "character". One Chinese word, one English word, one number, or one symbol typically counts as one token. Tokenizers differ across models, so conversion ratios vary.

      The `usage` field in each response reports the tokens actually consumed, and it is also the basis for platform billing.
    </Card>
  </Tab>
  <Tab title="Context window">
    <Card title="Context Window" icon="window">
      The context window is the maximum number of tokens a model can process in a single request. It includes:

      - The user's input
      - The model's generated reply
      - Intermediate content produced during reasoning or tool calls

      <Danger>
        **What happens if the context window is exceeded?**

        The request may fail with a context-length error, and the quality and coherence of the model's answers may degrade.
      </Danger>

      Check each model's context limit in the [Model overview](/en/models), and budget for combined input and output in long conversations.
    </Card>
  </Tab>
</Tabs>
