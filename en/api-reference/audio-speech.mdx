**POST** `/v1/audio/speech`

Generates audio content from a text description (`caption`). The current model is `MiniMax-Music3`, and the `caption` field in the request body must be a non-empty string.

<RequestExample>

```bash cURL
curl http://api.dev.origin-power.com/v1/audio/speech \
  -H "Authorization: Bearer $ORIGIN_POWER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "MiniMax-Music3",
    "caption": "An upbeat electronic background track for a product demo video, about 30 seconds long"
  }'
```

</RequestExample>

<ResponseExample>

```text Response
audio/mpeg binary content (audio stream response body, omitted here)
```

</ResponseExample>

## Request body

<ParamField body="model" type="string" required>
  Model name, currently `MiniMax-Music3`.
</ParamField>

<ParamField body="caption" type="string" required>
  A non-empty string describing the style and content of the audio to generate. The server rejects an empty `caption`.
</ParamField>

Other optional fields (duration, sample rate, output format, etc.) follow the backend implementation.

## Example request

```bash
curl http://api.dev.origin-power.com/v1/audio/speech \
```

## Response

The endpoint returns the generated audio content. Treat an actual call as the source of truth for the response structure.

<Warning title="The request schema follows the final backend implementation">
  Before going live, run one test call with a non-empty `caption` to confirm the field names and response structure. Do not submit an empty `caption` — the server errors with MiniMax Music 3 caption (instructions) must be a non-empty string.
</Warning>
