**DELETE** `/api/v3/videos/{task_id}`

Cancels a video generation task submitted with your own API key. Behavior depends on the task state: only **queued (`queued`)** tasks can be cancelled, and cancelling them is **not billed** (the pre-authorization is refunded automatically). A **generating (`processing`) task cannot be cancelled** — it completes normally and is billed as usual (consistent with the official MiniMax API). For music tasks, see [Cancel music task](/en/api-reference/music-task-cancel).

<RequestExample>

```bash cURL
curl -X DELETE http://api.dev.origin-power.com/api/v3/videos/video_xxx \
  -H "Authorization: Bearer $ORIGIN_POWER_API_KEY"
```

</RequestExample>

<ResponseExample>

```json Cancelled (queued)
{ "data": { "task_id": "video_5f3ae21", "action": "cancelled", "status": "cancelled" } }
```

</ResponseExample>

## Cancellation behavior by task state

| Task state | HTTP | Response | Billing |
| :--- | :--- | :--- | :--- |
| `queued` | 200 | `{"data":{"task_id":"...","action":"cancelled","status":"cancelled"}}` | Not billed (pre-authorization refunded) |
| `processing` (generating) | 409 | `Conflict`: `task is in working state and cannot be cancelled; it will complete normally and be billed` | Generation completes and is billed normally |
| `completed` / `failed` / `timeout` (terminal) | 409 | `Conflict`: `task already finished and cannot be cancelled` | — |
| Task does not exist / another key's task | 404 | `NotFound`: `task not found` | — |
| Malformed `task_id` | 400 | `BadRequest`: `invalid task_id: expected video_ prefix with 24 hex characters` | — |

## Cancellation rules

* You can only cancel tasks submitted with your own API key (ownership is verified by key fingerprint; another key's task returns 404, without revealing whether it exists)
* After a queued task is cancelled, [Query a video task](/en/api-reference/video-task-query) reports a `failed` terminal state with `error` set to `cancelled by user ... (queued, no charge)`
* Query parameters (such as `?dry_run=1`) are ignored
* Task records are not deleted on cancellation and remain queryable

<Note title="Failures are not billed">
  A queued task that was cancelled is not billed; tasks that end `failed` for other reasons are also not billed, and the pre-authorization is refunded automatically. Fix the parameters and resubmit.
</Note>
